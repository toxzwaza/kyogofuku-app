## 0. 進め方
- ブランチ：`main` から `feature/photo-slot-frames` を作る（今の `feature/credit-management` とは分ける）。
- ローカル（OrbStack）で作り、テストと画面の確認をしてから、村上さんの承認を得て本番に出す。
- 本番に出すときの手順（データの移し方）は 6 章。空き枠の予定を消すところは、件数を見せて承認を得てから行う。

## 1. データ（マイグレーション）

### 1-1. `photo_studios` に列を足す
| 列 | 型 | 既定 | 意味 |
|---|---|---|---|
| `shop_group` | string(20) nullable | null | 店舗グループ（okayama／fukui）。`shops.group_key` と同じ値 |
| `is_active` | boolean | true | 無効にすると、選択肢と枠作成に出さない（今の枠・予約は残す） |
| `default_start_time` | time nullable | null | 既定の開始時刻（最初の枠） |
| `default_end_time` | time nullable | null | 既定の終了時刻（最後の枠の終わり） |
| `default_capacity` | unsigned tinyint | 1 | 枠を作るときの既定の定員 |

- 営業時間が空のスタジオは、枠作成の画面で「営業時間が未登録です」と出して作れないようにする（各店舗にマスタ登録してもらうため）。

### 1-2. `photo_studio_weekday_hours`（新規）
| 列 | 型 | 意味 |
|---|---|---|
| `id` | | |
| `photo_studio_id` | FK（cascadeOnDelete） | |
| `weekday` | unsigned tinyint | 0＝日〜6＝土（Carbon の dayOfWeek と同じ） |
| `start_time` / `end_time` | time | その曜日の開始・終了 |

- 一意：（`photo_studio_id`, `weekday`）。行がある曜日＝マスタ画面でチェックを入れた曜日。

### 1-3. `photo_slots` を変える
- `seat_no`（unsigned tinyint、既定1）を足す。今の行はすべて1になる。
- 一意の制約 `uq_photo_slot`（スタジオ・日・時刻）を外し、（スタジオ・日・時刻・`seat_no`）で作り直す。
  - 詳細未決定の行はスタジオ・日・時刻が NULL なので、今と同じく制約にかからない。
- 1行＝枠の席1つ＝お客様1人まで、は変えない。今の顧客詳細・一覧・LINE マイページのコードはそのまま動く。

## 2. 権限と見える範囲

- **権限は今回設けない**（2026-11-19 村上さん）。前撮りの操作は、ログインしたスタッフ全員ができる。`users` に列も足さない。
- 権限は taskboard の案件「権限機能の整備」で、権限マスタ＋スタッフへのひも付けの形でまとめて作る。前撮りで権限を設ける場所（マスタの登録・変更、枠の作成・追加・定員の変更・空き枠の削除）は `docs/20261119_権限機能の整備_権限を設ける場所.md` に記録した。
- あとで権限を差し込みやすいよう、権限を設ける予定の操作は、コントローラのメソッドを分けておく（マスタ用・枠の管理用・予約用）。画面のボタンも、あとで1つの条件で隠せるように、まとまった場所に置く。
- 見える範囲：スタジオと枠を、ログインした人の店舗グループに絞る。
  - グループ＝`$user->visibleShopIds()` の店舗の `group_key`（`Shop` のグローバルスコープと同じ考え方）。システム管理者は全部。
  - `PhotoStudio` にスコープ `visibleToUser()` を作り、一覧・枠作成・顧客詳細の選択肢で使う。`PhotoSlot` はスタジオ経由で絞る（詳細未決定の行は、担当店舗で絞る）。
  - グローバルスコープにはしない（夜間のコマンドや LINE マイページで、知らないうちに絞られないように）。

## 3. 画面

### 3-1. スタジオのマスタ（`PhotoStudio/Index・Create・Edit.vue` を直す）
- 一覧：名前・店舗グループ・営業時間（既定と、曜日ごとの例外）・既定の定員・有効／無効。
- 登録・編集の画面に足す項目：
  - 店舗グループ（岡山／福井。自分のグループだけ選べる）
  - 有効／無効
  - 既定の開始・終了時刻（30分単位の選択肢。開始 < 終了）
  - 既定の定員（1〜10）
  - 曜日ごとの営業時間：月〜日のチェック。チェックを入れた曜日だけ、開始・終了の時刻の欄が出る
- 画面の下に「この営業時間でできる枠」の例を出す（例：「平日 9:00〜16:30 の16枠／土 8:30〜15:30 の15枠」）。
- 今回は誰でも登録・変更できる（権限機能を作るときに、管理者だけにする予定）。

### 3-2. 枠をまとめて作る（`PhotoSlot/Create.vue` を作り直す。イベント枠の `Timeslot/Bulk.vue` と同じ流れ）
1. **条件**：スタジオ（1つ）・期間（最大93日）・除外する曜日（初期値なし）・除外する日。
2. **プレビュー**（`POST photo-slots/bulk/preview`。DB は変えない）：日ごとの行を出す。
   - 各行：日付・曜日・使う営業時間（曜日の例外か既定か）・できる枠（時刻のチップ。チップに定員）・状態（作成／作成済み／過去／除外）
   - その日にもう枠がある時刻は「作成済み」として灰色で出し、作らない。
3. **保存の前に直す**（画面の中だけで直す。サーバーには保存のときにまとめて送る）
   - 日ごとのチェックで、その日を作る／作らない
   - 時刻のチップを外す（×）・時刻を足す（30分刻みの選択肢から。営業時間の外も選べる）
   - チップをクリックして定員を変える（1〜10）
   - 「全部の日にこの変更をかける」ボタン（例：全部の日の 12:00 を外す）
4. **保存**（`POST photo-slots/bulk`）：送られた「日付 → [時刻・定員]」の一覧を、サーバーでもう一度確かめて登録する。
   - 確かめること：スタジオが自分のグループか、30分刻みか、定員が1〜10か、日付が期間の中か、件数が上限（3000席）以下か
   - もうある時刻は飛ばす（上書きしない）。定員3なら席1〜3の3行を作る。
   - まとめて1つのトランザクションで登録し、activity log に「誰が・どのスタジオに・何日分・何席」を残す。
   - 空き枠なので、カレンダーの予定は作らない。

### 3-3. 前撮り一覧（`PhotoSlot/Index.vue`）
- 今の一覧の作りは残し、次を直す：
  - 自分の店舗グループの枠だけを出す（サーバーで絞る）
  - 初期表示は今日以降。過去の分は期間を選んだときだけ読み込む
  - 同じ時刻の席をまとめて「10:00　2/3（予約2・定員3）」のように出す
  - ボタン：「枠をまとめて作る」「この時刻に1枠足す」「定員を変える」「空き枠を消す」（今回は全員に出す。権限機能で管理者だけにする予定）
- **表の画面**（今回作る。7章 D1）：一覧の上に「表／リスト」の切り替えを置き、表を初期表示にする。
  - スタジオはチェックボックスで複数選ぶ（自分のグループのスタジオ。既定は動いているスタジオすべて。選んだものはブラウザに覚える）。表示は1か月（前の月／今月／次の月／月を選んで移動）。今月以降で枠のある月をボタンで並べ、押すとその月へ移る。（2026-11-19 村上さんの指示で、1スタジオ・1週間から変更）
  - 登録済みの枠がある日・時刻だけを出す。縦が時刻（枠のある時刻だけ）、横が「日付×スタジオ」（その日に枠のあるスタジオだけ。見出しにスタジオ名と担当店舗）。
  - マスの中：席ごとにお客様の名前（予約あり）か「空き」。定員3なら3行。枠がないマスは灰色。
  - 色：空きあり（白）／満員（緑）／枠なし（灰）。今日の列に印。
  - 予約のあるお客様の名前をクリック → 顧客詳細へ。空きの席をクリック → 「お客様を選んで予約」の小さい画面（お客様の検索 → 担当店舗・担当者 → 予約）。
  - 枠のあるマスの「＋」で、その時刻に1枠足す／定員を変える（今回は全員。権限機能で管理者だけにする予定）。枠のない時刻に新しく作るときは「枠をまとめて作る」を使う。
  - 読み込みは選んだ月の分だけ（`GET photo-slots/grid?studio_ids[]=&month=YYYY-MM`）。
  - スマホでは横にスクロールできるようにし、時刻の列を固定する。

### 3-4. 顧客詳細の前撮りのモーダル（`Customer/Show.vue`）
- スタジオの選択肢を、自分のグループの有効なスタジオに絞る。
- 日付を選ぶと、その日の時刻ごとに「空き n／定員 m」を出す。満員の時刻は選べない。
- 選ぶのは「時刻」。どの席に入れるかはサーバーが決める（空いている一番小さい席）。

### 3-5. 画面の中のマニュアル（`Manuals/PhotoSlot.vue`）
- マスタ登録 → 枠をまとめて作る → 予約を入れる、の順で書き直す。

## 4. 処理

### 4-1. `PhotoStudioHours`（新しいサービス）
- `timesFor(PhotoStudio $studio, Carbon $date): array` … その日の時刻の一覧（曜日の例外があればそれ、なければ既定。30分刻み、終了の30分前まで）。
- 枠作成のプレビューとマスタ画面の例の両方で使う。

### 4-2. `PhotoSlotBulkController`（新規。`TimeslotBulkController` をもとにする）
- `create`：スタジオの一覧（自分のグループ・有効・営業時間あり）を渡す。
- `preview`：条件から日ごとの案を返す（`PhotoStudioHours` ＋ もうある時刻）。
- `store`：3-2 の4のとおり。

### 4-3. `PhotoSlotBookingService`（新規。予約の入れる・移す・取り消すを1か所にまとめる）
- `assign(Customer, studioId, date, time, attrs)`
  1. トランザクションの中で、その時刻の席の行を `lockForUpdate()` で取る
  2. お客様のいない一番小さい席を選ぶ。なければ「満員です」のエラー
  3. 担当店舗が、そのスタジオの店舗グループに属するか確かめる
  4. 席にお客様・担当などを入れ、予定（30分）を作ってカレンダーに送る（トランザクションのあと）
- `move(PhotoSlot $from, studioId, date, time)`：新しい席に `assign` と同じ手順で入れ、元の席は空きに戻して予定を消す。元が詳細未決定なら、元の行は消す。
- `release(PhotoSlot $slot)`：お客様・担当・プラン・ラベル・備考を空にして、予定を消す。席の行は残す。
- `setUndecided(Customer, attrs)`：詳細未決定の行を作る（今と同じ）。予定は作らない。
- 今のコントローラの次の処理を、このサービスを呼ぶように変える：
  - `CustomerController@storePhotoSlot`・`@updatePhotoSlot`（不具合1・4・5）
  - `PhotoSlotController@update`・`@bulkUpdate`・`@unassign`（不具合3）

### 4-4. 予定とカレンダー
- 予定（`StaffSchedule`）は**予約が入ったときに作り、取り消したら消す**。長さは30分。
- 予定の作り方を `PhotoSlotScheduleService`（今の `createStaffScheduleForSlot` を移す）にまとめ、参加者＝担当店舗のスタッフ、送り先＝その店舗のカレンダー。
- 担当店舗が変わったら、参加者を作り直して送り直す（不具合5）。
- `PhotoSlotObserver`：
  - `updated`：時刻を変えたときの終わりを「＋1時間」から「＋30分」に直す。お客様が空になったら予定を消す（どの画面から外しても同じになるように）。
  - `deleting`：今のまま（予定とカレンダーの予定を消す）。
- `ScheduleController@update`（不具合2）：前撮りの予定（`photo_slot_id` あり）は、予定の画面では日時を変えられないようにする（422 と「前撮りの日時は前撮りの画面で変えてください」）。同じ日・スタジオの全部の枠を動かす処理は消す。
- 昔の予定作成ボタン2つ（`PhotoSlotController.php:462`・`:550`）は、今は必ずエラーになるので、ルートと一緒に消す。

### 4-5. テスト（`tests/Feature/PhotoSlot/`）
- マスタ：保存できる／曜日の例外が使われる
- 枠作成：プレビューの時刻がマスタどおり／直した内容で保存される／もうある時刻は飛ばす／ほかのグループのスタジオは 403
- 予約：満員なら入らない／移すと元が空きに戻る（消えない）／取り消すと予定が消える／詳細未決定から移すと元の行が消える／ほかのグループの担当店舗は入れられない
- 同時操作：同じ最後の1席に2人が入れようとしても1人だけ入る
- 予定：予約で30分の予定ができる／空き枠では予定ができない／予定の画面から前撮りの日時を変えられない

## 6. 本番に出すときの手順（データの移し方）
1. 本番の DB のバックアップを取る。
2. 件数を数えて村上さんに見せる：スタジオの数、枠の数（予約あり／空き）、空き枠の予定の数（Google に送ってあるものを含む）。
3. デプロイしてマイグレーションを流す（今の枠は全部 `seat_no=1` になる）。
4. スタジオに店舗グループを付ける（一覧を見せて承認を得てから）。
5. 空き枠の予定を消すコマンド `photo-slots:purge-vacant-schedules` を、まず `--dry-run` で流して件数を見せ、承認を得てから本番で流す（Google のカレンダーの予定も消す）。
6. 各店舗に、スタジオのマスタの営業時間を登録してもらう（マニュアルを渡す）。
