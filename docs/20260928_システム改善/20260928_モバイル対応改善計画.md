# モバイル対応（iPad / iPhone）改善計画（2026-09-28）

## 背景

現場スタッフは PC より **iPad / iPhone で本システムを使っている**（2026-09-28 判明）。
しかし現システムは **デスクトップ優先設計**。モバイルでの使いやすさを底上げすれば、
「年配者を含む全員が使いやすい」というモットーに最も直接的に効く。

コード調査（`app/` `resources/js/` の実ファイル確認）で実態を把握した結果を以下にまとめる。

## 現状評価

### ✅ 既にできている点（土台はある・ゼロからではない）
- **レスポンシブ基盤**：`AdminLayout.vue` はモバイルでサイドバーをドロワー化（ハンバーガー）済み。
- **モバイルカード化の仕組み**：`Components/UI/DataTable.vue` は画面幅で
  「テーブル↔カード表示」を自動切替（`md:hidden`）。予約一覧などで活用済み → **横展開すればよい**。
- **PWA 基盤**：`manifest.webmanifest`・`theme-color`・アイコン・`display: standalone` 完備。
  → **iPad/iPhone のホーム画面に追加すれば、アプリのように全画面で使える**（後述）。
- **勤怠打刻パネル**（`PunchPanel.vue`）：モバイルで1列化するなど配慮あり。

### ⚠ モバイルで使いにくい原因（影響度の大きい順）

| # | 課題 | 根拠 | 修正コスト |
|---|------|------|----------|

## 改善項目と進め方

### 第1弾：全画面に即効く底上げ（低コスト・繁忙期前に実施可）
共通設定・共通コンポーネント1箇所の変更で全画面に波及する。**費用対効果が最大**。

- **M1** viewport を `user-scalable=yes, maximum-scale=5`（または maximum-scale 撤廃）に変更。← 最優先・1行
- **M2** Button の sm/md のデフォルト高さを 44px 以上に引き上げ（または sm を非推奨化）。
  サイドバーのリンク・ページングのタップ領域拡大。
- **M3** Tooltip を hover 依存から `focus/tap` + 常時表示の補足に置き換え（グループ1の U2 と統合）。
- **M5** input/select の最小 font-size を 16px に統一（iOSズーム防止）。

※ M1〜M5 は「改善候補リスト グループ1（文字・ボタン底上げ）」と重なる。**モバイル対応と底上げは一体で実施**する。

### 第2弾：画面ごとのモバイル最適化（中コスト）
- **M4** 横スクロール放置のテーブルを、既存の `DataTable.vue`（カード自動切替）へ順次移行。
  よく使う画面（勤怠履歴・承認・予約・顧客一覧）から着手。
- **M6** よく使う操作（出勤/退勤・予約確認・顧客検索）へ素早く届くボトムナビ or クイックアクションの追加。
- **M7** 固定ヘッダー・高さ計算を `dvh` ベースに統一し iOS のずれを解消。

### 第3弾：仕上げ（要実機確認）
- **M8** タッチでのドラッグ&ドロップ対応（画像並び替え等）。実機で挙動確認のうえ対応。

## PWA 活用（現場運用の提案・追加開発ほぼ不要）

PWA 基盤は既にあるため、**iPad/iPhone のホーム画面に「京呉服アプリ」として追加**すれば：
- Safari の URL 入力・ブックマークを探す手間がなくなる（年配者に優しい）
- アドレスバーが消えて**全画面**で使える（M7 の高さずれも軽減）
- アイコンをタップするだけで起動＝「アプリを使っている」感覚になる

→ 現場端末へのホーム画面追加の手順書を作れば、追加開発なしで体験が向上する。
（`icon`・名称・起動画面の見栄えは軽微な調整余地あり）

## 実機検証の重要性

コード評価に加え、**実際に iPad / iPhone で主要画面を触っての検証が必須**。
Playwright のモバイルエミュレーション（iPad/iPhone のビューポート）で開発環境を確認し、
最終的には実機（現場と同じ機種）で確認する。

## この計画の位置づけ

- 行動計測（Clarity）は保留中だが、**モバイル対応の課題はコード調査で十分に特定済み**のため、
  計測を待たずに第1弾から着手できる。
- 第1弾（M1〜M5）は「改善候補リスト グループ1」と統合し、最優先で試作 → before/after 確認 → 適用。
