## Phase 2：本番デプロイ（手順書準拠）

### 2-1. SSH接続・現状記録

```bash
ssh kyogofuku
cd /srv/laravel-apps/event-reserve
docker compose ps
PREV_HEAD=$(docker compose exec -T app git rev-parse HEAD)
echo "ROLLBACK target: $PREV_HEAD"   # ← 必ず記録
```

### 2-2. DBバックアップ（必須）

```bash
DB_NAME=$(docker compose exec -T app grep '^DB_DATABASE=' .env | cut -d= -f2 | tr -d '\r')
DB_USER=$(docker compose exec -T app grep '^DB_USERNAME=' .env | cut -d= -f2 | tr -d '\r')
DB_PW=$(docker compose exec -T app grep '^DB_PASSWORD=' .env | cut -d= -f2 | tr -d '\r')

cd /srv/laravel-apps/shared
docker compose exec -T db mariadb-dump -u $DB_USER -p"$DB_PW" $DB_NAME \
  > /tmp/event_reserve_backup_$(date +%Y%m%d_%H%M%S).sql
ls -lh /tmp/event_reserve_backup_*.sql | tail -1
```

### 2-3. コード反映・migration・ビルド

```bash
cd /srv/laravel-apps/event-reserve
docker compose exec app git pull origin main
docker compose exec app git rev-parse HEAD          # Phase1-3のhashと一致確認

docker compose exec app composer install --no-dev --optimize-autoloader

docker compose exec app php artisan migrate:status | grep -i pending   # 3本のはず
docker compose exec app php artisan migrate --force

# フロントビルド（node の場所は手順書 STEP8 参照）
docker compose exec app npm ci && docker compose exec app npm run build
```

### 2-4. キャッシュ再構築（**restartなし** — 村上さん指示 2026-07-26）

```bash
docker compose exec app php artisan optimize:clear
docker compose exec app php artisan config:clear
docker compose exec app php artisan config:cache
```

> **注**: `docker compose restart app` は行わない（サービス断ゼロ）。PHPコードの反映は opcache の
> タイムスタンプ検証（既定で有効）により自動追従する想定。万一 2-5 のスモークテストで
> 旧コードが表示され続ける場合のみ、村上さんに確認のうえ restart を検討する。

## Phase 4：ロールバック計画

| 状況 | 対応 |
|------|------|
| コード起因の障害 | `docker compose exec app git reset --hard $PREV_HEAD` → composer/npm再実行 → キャッシュ再構築 → restart |
| マイグレーション起因 | `php artisan migrate:rollback --step=3`（downあり）。カラム追加のみでデータ破壊なし |
| マスタ投入ミス | storage のバックアップJSONから復元、または Phase 2-2 のDB dumpからテーブル単位でリストア |
| 全面リストア | `/tmp/event_reserve_backup_*.sql` を shared_db へ流し込み（最終手段） |
