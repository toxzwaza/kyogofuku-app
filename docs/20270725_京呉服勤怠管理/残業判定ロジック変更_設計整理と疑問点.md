# 勤怠：残業判定ロジック変更 — 設計整理・疑問点・勤務属性リスト

- **作成日**：2026-07-25
- **対象アプリ**：kyogofuku-app（`feature/attendance-fix`）
- **関連資料**：`勤務属性別_各店舗スタッフ状況まとめ.md`（2026-07-24）
- **目的**：残業判定を「勤務属性ごとにパターン方式／残業閾値方式を切替可能」に変更するための設計整理と、実装前の確認事項の洗い出し。

---

## 1. やりたいこと（村上さん指示の要約）

1. 現状、残業は **すべて「ベースの勤務時間（＝所定終業時刻）を超えた分」** で算出している。
2. これを、**各勤務属性に「残業時間閾値」を登録**しておき、**1日の勤務時間がその閾値を超えた分を残業**とする方式に変更したい。
3. **正社員は現状どおりパターンABCを登録**し、それを元に算出する（**早出も残業も**パターン基準）。
4. **勤務属性ごとに「パターン方式」か「残業閾値方式」かを切り替えられる**ようにする。

## 2. 現状ロジックの分析（コード根拠）

中核は `app/Services/AttendancePayrollTimeService.php`。

| 処理 | メソッド | 現状の挙動 |
|------|----------|-----------|
| ベース窓の解決 | `resolveBaseWindow()` | `勤務属性 × 会社カレンダーのパターン(A/B/C) × 平日/土日` から `work_start_time`〜`work_end_time` を取得。**全属性がこの方式に依存**。 |
| 残業（分） | `rawOvertimeMinutesAfterBaseEnd()` | **退勤打刻 − baseEnd** の超過分（baseEnd以降にかかる休憩は控除）。 |
| 早出 | `payrollClockInAt()` / `payrollClockInCategory()` | baseStart より前の打刻を早出扱い（`start_early_threshold_minutes` で丸め・境界判定）。 |
| 遅刻・早退 | `monthlyMetricsForRecord()` | baseStart 超過＝遅刻、baseEnd 未満＝早退。 |
| 残業丸め | `roundOvertimeMinutes()` | `overtime_rounding_unit_minutes` 刻みで**切り捨て**。 |
| 深夜残業 | `nightWorkMinutesBetween()` | 22:00〜翌5:00 に重なる分。残業のうち深夜帯にかかる分を「深夜残業」として普通残業から分離。 |

> **重要**：現状は「残業閾値」という概念がコード上に存在しない。残業は常に **baseEnd（所定終業時刻）超過** で決まる。`work_attributes` マスタには `name` / `sort_order` しか無く、閾値カラムも方式フラグも無い。

### 現状のデータモデル
```
work_attributes                : id, name, sort_order
work_attribute_pattern_times   : work_attribute_id, pattern(A/B/C), day_type(weekday/weekend),
                                 work_start_time, work_end_time
users.work_attribute_id        : スタッフに紐づく勤務属性（nullは対象外）
attendance_payroll_settings    : 全社共通の丸め設定（属性別ではない）
```

## 3. 新方式の設計案（村上回答 反映済み・確定版）

### 3-0. 設計の軸を2つに分離（時短ハイブリッド対応）

村上回答で「時短はパターンを登録しつつ残業は閾値で算出」というハイブリッドが必要になったため、
**「残業の決め方」**と**「パターン時刻の有無（＝早出・遅刻・早退の判定可否）」**を独立した2軸として設計する。

| 属性タイプ | パターン時刻 | 早出/遅刻/早退 | 残業の決め方 | 残業閾値 |
|-----------|:---:|:---:|------|:---:|
| **正社員** | 登録あり | 判定する | **ベース終業(baseEnd)超過** | 不要 |
| **正社員(時短)** | 登録あり | 判定する | **実働 − 閾値**（ハイブリッド） | 必要 |
| **パート各種** | 登録なし | 判定しない | **実働 − 閾値** | 必要 |

- 早出・遅刻・早退は「パターン時刻（baseStart/baseEnd）が解決できる属性」でのみ算出する。パートは登録しないため自動的に非算出（Q2確定）。
- 残業は `overtime_mode` で分岐：`base_end`（従来＝退勤 − baseEnd）／`threshold`（実働 − 閾値）。

### 3-2. マスタ変更案（マイグレーション）

**属性単位（`work_attributes`）**
```
+ overtime_mode              ENUM('base_end','threshold')  デフォルト 'base_end'
+ overtime_threshold_minutes INT NULL   // overtime_mode='threshold' 時に使用（480=8h, 470=7h50min）
```
- `base_end`：従来どおり `work_attribute_pattern_times`（A/B/C × 平日/土日）の baseEnd 超過で残業。
- `threshold`：**実働 − `overtime_threshold_minutes`** で残業。パターン時刻は「登録があれば」早出/遅刻/早退の判定にのみ使う（時短）。無ければ残業だけ算出（パート）。

**個人単位（`users`）— 休憩方式（Q3確定）**
```
+ break_mode              ENUM('fixed','manual')  // fixed=所定固定休憩 / manual=打刻時にモーダル入力
+ scheduled_break_minutes INT NULL                // break_mode='fixed' のときの所定休憩（分）
```
- **fixed**：休憩が一定の人（1h=60 / 1h25min=85 / 1.5h=90 等）は所定値を登録し、実働から一律控除。休憩打刻は不要。
- **manual**：休憩が変動・複数ある人は登録せず、**勤怠打刻画面の「休憩」ボタン → 休憩登録モーダル**で都度入力（`attendance_breaks` に記録）。実打刻ベースで控除。
- 休憩方式は**個人ごとに異なる**（同じパート属性内でも固定と変動が混在するため、属性ではなくユーザーに持たせる）。全モード共通で使う。

### 3-3. 残業計算（モード別）

**共通：休憩控除**
```
休憩控除 = (break_mode=fixed) ? scheduled_break_minutes : 休憩打刻合計
```

**base_end（正社員）**
```
残業分 = 退勤打刻 − baseEnd（baseEnd以降にかかる休憩は控除）   // 現状ロジックのまま
```

**threshold（パート・時短）**
```
実働分 = (退勤打刻 − 出勤打刻) − 休憩控除
残業分 = max(0, 実働分 − overtime_threshold_minutes)
残業分 = roundOvertimeMinutes(残業分)   // 既存の切り捨て丸めを流用（A-3=流用で確定）
```
- **深夜残業（確定）**：threshold の残業分のうち、**退勤時刻から遡った末尾部分**が 22:00〜翌5:00 に重なる分を深夜残業として分離（既存 `nightWorkMinutesBetween` を末尾区間に適用）。
- **給与用の出勤/退勤時刻（B-4=確定）**：threshold かつパターン時刻なし（パート）は実打刻を採用（出勤は始業丸めのみ）。時短はパターンがあるため出勤/退勤の表示は baseStart/baseEnd 基準を用いる。
- 早出・遅刻・早退：パターン時刻が解決できる属性（正社員・時短）のみ算出。パートは非算出（Q2）。

### 3-4. 正社員パターン時刻（Q4確定 — 画像より）

| パターン | 曜日区分 | 業務開始 | 業務終了 |
|:-:|:-:|:-:|:-:|
| A | 平日 | 09:45 | 19:00 |
| A | 土日 | 09:45 | 19:00 |
| B | 平日 | 09:45 | 20:00 |
| B | 土日 | 09:45 | 20:00 |
| C | 平日 | 13:00 | 20:00 |
| C | 土日 | 13:00 | 20:00 |

- 現時点は平日・土日で同値だが、**day_type を分けて登録**し将来の差異に備える（枠は分離管理）。
- 会社カレンダーで日ごとに A/B/C が決まる（既存仕様）。

## 4. 疑問点

### ✅ 確定済み（村上回答）
- **Q1（D-1）パート閾値の粒度** → 閾値ごとに属性を分ける（パート(8h)／パート(7h50)）。
- **Q2（B-1/B-2）閾値方式の早出・遅刻・早退** → 判定しない。残業のみ算出。
- **Q3（A-2）休憩の取り方** → 個人ごとに `fixed`（所定固定を登録）/`manual`（打刻画面の休憩ボタン→モーダル入力）を選べる。
- **Q4（C-2）正社員の平日/土日時刻** → day_type を分けて登録（値は §3-4 の画像どおり）。

### ✅ 追加確定（村上回答・第2ラウンド）
- **D-2. P(S)（試用中パート）** → **専用属性「パート(試用/正社員候補)」に分ける**（将来S化の把握のため）。
- **E-1. 過去分の再計算** → **切替日以降のみ新方式**。切替日より前のレコードは据え置き（再計算しない）。
- **B-3. 閾値方式の深夜残業** → **深夜帯にかかる分を分離**（末尾区間に既存ロジックを適用）。
- **C-3. 時短** → **パートと同様に残業は閾値超過で算出**。ただしパターンは登録する（早出/遅刻/早退はパターン基準）＝ハイブリッド（§3-0）。
- **A-3 / B-4 / C-1 / D-3** → 推奨デフォルトで確定：
  - A-3：残業丸めは既存 `overtime_rounding_unit_minutes`（切り捨て）を流用。
  - B-4：給与用時刻は §3-3 のとおり（パートは実打刻採用）。
  - C-1：正社員（base_end）に閾値は登録しない。
  - D-3：「×」は勤務属性を割り当てない（work_attribute_id=null）＝集計対象外。マスタに「×」は作らない。

> **未確定は残っていない。以下の設計で実装可能。**

## 6. 実装スコープ（確定）

1. **マイグレーション**
   - `work_attributes` に `overtime_mode`('base_end'|'threshold') / `overtime_threshold_minutes` 追加。
   - `users` に `break_mode`('fixed'|'manual') / `scheduled_break_minutes` 追加。
   - `attendance_payroll_settings` に **閾値方式の切替日**（例 `threshold_effective_date`）を追加（E-1：切替日以降のみ新方式）。
2. **モデル**：`WorkAttribute`（fillable・定数）、`User`（休憩方式）を更新。
3. **管理画面**：勤務属性マスタの登録/編集UIに overtime_mode・閾値を、スタッフ編集に休憩方式・所定休憩を追加。
4. **打刻画面**：`break_mode='manual'` の人に「休憩」ボタン → 休憩登録モーダルを実装（`attendance_breaks` へ記録）。
5. **`AttendancePayrollTimeService`**：
   - 休憩控除を `break_mode` 対応に共通化。
   - `overtime_mode='threshold'` の残業計算パス（実働 − 閾値、末尾区間の深夜分離）を追加。
   - 切替日より前のレコードは従来挙動を維持（新方式を適用しない）。
   - `payrollPayloadForRecord()` / `monthlyMetricsForRecord()` / `simulatePayroll()` を全モード対応に。
6. **マスタ投入**：勤務属性リスト（§5）の登録＋各スタッフの属性・休憩方式割り当て。
7. **テスト**：base_end 非回帰／threshold（パート）／ハイブリッド（時短）／切替日境界／深夜残業。
