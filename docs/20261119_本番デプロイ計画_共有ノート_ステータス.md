## 守ること（手順書より）

1. **コンテナを消さない**。`docker compose down`・`build`・`rm` は使わない
2. **コンテナの中の `.git` と `.env` が本番の正本**。git pull・migrate・npm build はすべてコンテナ `event_app` の中で行う
3. **migrate の前に DB のバックアップを取る**
4. キャッシュは `optimize:clear` → `restart` → `config:clear` → `config:cache` の順
5. 本番への書き込み（push・pull・migrate・build・restart）は村上さんの承認のあとに行う

> **【重要】2026-11-19 時点では `docker compose exec app`・`docker compose restart app` を使わない。**
> いま動いている `event_app`（2026-11-15 起動）は docker compose の管理から外れており、compose の `app` は止まっている古いコンテナ `event_app_old` を指している（`docker compose exec app` は「service "app" is not running」になる。`docker compose restart app` は古いコンテナを動かしてしまうおそれがある）。
> この手順書では **`docker exec event_app …`・`docker restart event_app`** を使う。DB も **`docker exec shared_db …`** を使う。

## 変更の中身

| 種別 | 内容 |
|---|---|
| migration | **1本**（`2026_11_19_100000_add_status_to_incidents`）。`incidents` に `status`（既定値 open）・`status_changed_by`・`status_changed_at` と索引 (group_key, status)、`incident_comments` に `type`（既定値 record）・`from_status`・`to_status`・`edited_at` を追加。表 `incident_comment_revisions` を新しく作る。**既存の記録はすべて「未対応」、既存の経過はすべて「対応記録」になる** |
| バックエンド | `IncidentController`（storeDecision・updateStatus・updateComment を追加、一覧に st の絞り込みと statusCounts）、`Incident`・`IncidentComment`・`IncidentCommentRevision`（新規）、`routes/web.php` にルート3本を追加 |
| フロント | 共有ノートの一覧・詳細・入力・直す、`StatusBadge.vue`（新規）、`useIncidentFlow.js` → **npm run build が要る** |
| 依存パッケージ・.env・Seeder・cron | **変更なし** |
| 既存の機能への影響 | 共有ノートの中だけ。入力画面のボタン名「未対応」→「その場では対応していない」 |
