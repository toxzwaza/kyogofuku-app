## 2. 修正1：既読表示＋「未読のみ」トグル

### 背景
- 当初の「LINE受信」ブロックは**未読のみ表示**だった。
- 実データでは**未読がほぼ無く（受信52件中 未読1件）**、画面が空に見えて「何も表示されない」状態だった。
- 既読も確認したい・未読だけに絞りたい、の両方を切り替えられるようにする要望。

### 実装内容
- **バックエンド（`OverviewController`）**
  - 未読は全件（上限300・古い未読も漏らさない）＋**既読は直近200件**を取得してマージ。
  - 各メッセージに `is_unread` フラグ、各グループに `unread_count` / `total_count` を付与。
  - カード見出し用に `unread_total` / `total` を返却。
- **フロント（`Overview.vue`）**
  - ヘッダーに**「未読のみ」トグルスイッチ**を追加（既定ON）。
    - ON：未読を含むお客様のみ表示（従来挙動）。
    - OFF：既読も含めて全件表示。
  - 既読メッセージは**淡色表示**、未読は通常色＋**緑ドット**で区別。
  - グループ行のバッジ：未読あり→`未読 n`（緑）、既読のみ→`既読`（グレー）。
  - 並び順：**未読あり優先 → 最新受信順**。
  - 空状態に**「既読も表示する」導線**を設置（未読0件でも真っ白にならない）。

### 既読化の流れ（補足）
未読は、顧客／予約詳細でLINEスレッドを開いた時点で既存ロジック（`CustomerLineMessageController::contactMessages`）が `admin_read_at` を付与して既読化される。トグルOFFにすれば、その既読も遡って確認できる。

## 3. 修正2：担当店舗変更がLINEに反映されない不具合

### 症状
- あるユーザー（顧客）の担当店舗をセレクトボックスで「城東店 → 岡山店」に変更したが、
  - LINE新着**通知は城東店グループ**のまま届く。
  - オーバービューの「LINE受信」で**岡山店ユーザーに表示されない**。

### 根本原因
「担当店舗」が**2つの別カラム**に存在し、変更されるのは片方だけだった。

| 保存先 | 意味 | セレクトで変わる？ | LINEが見るのは？ |
|--------|------|:---:|:---:|
| `customers.shop_id` | 顧客マスタの担当店舗 | ✅ 変わる | ❌ |
| `customer_line_contacts.shop_id` | **LINE連携先の店舗** | ❌ 変わらない | ✅ **これを見る** |

- セレクトボックス（`CustomerLineSection.vue`）→ `CustomerController::updateResponsibleShop()` は **`customers.shop_id` だけ**を更新していた。
- `customer_line_contacts.shop_id` は **LINE連携した瞬間に `customers.shop_id` をコピーするだけ**で、その後の担当店舗変更に**追従する処理が存在しなかった**。
- 新着通知の送信先（`ShopLineGroupNotifier::resolveGroupId()`）も、オーバービューの表示判定（`OverviewController`）も、**`contact.shop_id`** を見るため、城東のまま据え置かれていた。

### 修正内容
`CustomerController::updateResponsibleShop()` を修正し、顧客の `shop_id` 更新と**同一トランザクション内**で、紐づく `CustomerLineContact.shop_id` も同じ店舗（null含む）へ同期更新するようにした。

```php
DB::transaction(function () use ($customer, $shopId) {
    $customer->update(['shop_id' => $shopId]);

    // 顧客の担当店舗に、紐づく LINE コンタクトの店舗も追従させる。
    CustomerLineContact::where('customer_id', $customer->id)
        ->update(['shop_id' => $shopId]);
});
```

### 既存データの是正
- 本修正は「**これから**担当店舗を変更する分」に効く。
- 修正デプロイ**前**にズレてしまった顧客は、デプロイ後に**担当店舗セレクトを再保存**すれば同期される（過去分が多い場合は一括是正スクリプトで対応可能）。

## 5. デプロイ手順と注意点（重要な学び）

本番には **npm（Node環境）が無い**ため、フロントの変更はローカルでビルドして配置する。

### 手順概要
1. **PHP**（`OverviewController` / `CustomerController`）… 本番コンテナ内 `git pull origin main` で反映（migration / composer 不要）。
2. **フロント**（`Overview.vue`）… **ローカルで `npm run build`**（本番と同じ環境）して、生成された Overview チャンクを本番の `public/build/assets/` へ配置。
3. キャッシュ再構築：`php artisan config:cache && route:cache && view:cache`。
4. 確認は**スーパーリロード（Cmd+Shift+R）**。

### ⚠️ ハマりどころ：ビルドのファイル名は「ビルド環境」に依存する
- Vite が出力するチャンクのファイル名（ハッシュ）は、**依存パッケージのバージョンやビルド環境によって変わる**。
- 別環境（例：別マシン）でビルドしたファイル名は、本番のファイル名と**一致しない**ことがある。
- そのため「特定の1ファイルだけ差し替え」を狙う場合は、**本番と同じ環境（＝普段ビルドしているローカル）でビルドして出たファイル名**を使うこと。
- ファイル名がコンテンツで変わる体系の場合は、`manifest.json` の更新も必要。**不整合を避ける最も安全な方法は、`public/build/` を退避してからローカルビルド版で差し替えること**（ローカルビルドは全ページ整合しているため他画面は壊れない）。

```bash
# 安全な切り戻し用の退避（本番コンテナ内、差し替え前に実行）
cp -r public/build /tmp/build_backup_$(date +%Y%m%d_%H%M%S)
```

## 7. 今後の拡張候補

- 未連携メッセージ（`LineUnknownInboundMessage` ＝顧客紐付け前の受信）の警告表示（最も見落としやすい）。
- 過去に担当店舗を変更した顧客の**一括是正スクリプト**（ズレが多数残っている場合）。
- 予約由来コンタクト（`event_reservation_id` 紐付け）の担当店舗変更時の同期（今回は顧客紐付けのみ対応）。
- **③ 自動同期の仕組み化**：`Customer` モデルの `updated` イベント（Observer）で `shop_id` 変更を検知し、`CustomerLineContact` を自動追従。更新経路が増えても同期漏れが起きない、最も堅牢な形。
