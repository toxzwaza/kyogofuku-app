# 本番データ → ローカル同期計画

- 作成日: 2026-05-16
- 最終更新: 2026-06-12（実運用に合わせて改訂）
- 対象システム: `京呉服平田/HP_WP/kyogofuku-app`（Laravel + MariaDB）
- 起案: 村上
- 目的: 追加開発・テスト用に本番DB＋画像ストレージを最新化する

---

## 1. 前提・方針

- **同期範囲**: DB 全64テーブル + `storage/app/public/` 画像
- **ローカルDB**: `localdb_prod` を本番データで**毎回上書き**する運用（`.env` は常時 `DB_DATABASE=localdb_prod`、切替不要）。
- **ローカルDBの実体**: macOS上の Docker コンテナ `akioka-mysql`（image: mysql:8.0、127.0.0.1:3306 公開）。ホストには `mysql` クライアントが無いので、すべて `docker exec` 経由で操作する。
- **本番DB接続**: `ssh kyogofuku`（SSH config エイリアス、160.251.139.12 / to-murakami）→ `docker exec shared_db mysqldump`（読み取りのみ）
- **本番 `.env` の正本**: `docker exec event_app cat /var/www/html/.env`（ホスト側 `/srv/.../app/.env` はマウントされておらず古い）
- **画像同期**: コンテナ内 `event_app:/var/www/html/storage/app/public/` を `docker cp` → rsync。ホスト側 `/srv/.../app/storage/...` は古いため使わない。
- **補正**: 取り込み後、`docs/本番同期後_店舗マスタ補正メモ.md` のSQLでGoogleカレンダーID／LINE Group IDをローカル用に置換（**本番カレンダー誤通知防止の最重要ステップ**）。
- **PHP コマンド**: システムの `php` は 8.1 で `vendor/autoload.php` が PHP>=8.2 要求で fatal。**Laravel 操作は `/opt/homebrew/opt/php@8.2/bin/php` を明示**して使う。

## 3. Phase 0: 事前準備

```bash
# 作業ディレクトリ
APP_DIR="/Users/to-murakami/業務データ/CC_会社/システム開発部門/京呉服平田/HP_WP/kyogofuku-app"
DUMP_DIR="/Users/to-murakami/業務データ/CC_会社/システム開発部門/京呉服平田/HP_WP/dump"
TS=$(date +%Y%m%d_%H%M)
mkdir -p "$DUMP_DIR"

# .env から DB認証情報を取り出して環境変数に入れる（会話・ログには値を出さない）
LOCAL_DB_PASS=$(/opt/homebrew/opt/php@8.2/bin/php -r '
$lines = file(".env", FILE_IGNORE_NEW_LINES);
foreach ($lines as $l) {
  if (preg_match("/^DB_PASSWORD=(.*)$/", $l, $m)) {
    $v = $m[1];
    if (strlen($v) >= 2 && (($v[0]==="\"" && substr($v,-1)==="\"") || ($v[0]==="\x27" && substr($v,-1)==="\x27"))) $v = substr($v,1,-1);
    echo $v;
  }
}')

# 0-1. （任意）ローカル localdb_prod の現状バックアップ
#   毎回上書き運用なので通常はスキップ可。前回同期から触ったテストデータを残したい時のみ実施。
docker exec -i -e PASS="$LOCAL_DB_PASS" akioka-mysql \
  sh -c 'mysqldump -h 127.0.0.1 -u to_murakami -p"$PASS" \
    --single-transaction --default-character-set=utf8mb4 localdb_prod' \
  > "$DUMP_DIR/local_localdb_prod_${TS}_pre_sync.sql"

# 0-2. ローカル storage/app/public のスナップショット（差分ロールバック用）
tar czf "$DUMP_DIR/local_storage_${TS}_pre_sync.tgz" \
  -C "$APP_DIR" storage/app/public
```

> **罠**: `akioka-mysql` コンテナ内では `to_murakami@localhost` が許可されておらず、`-h 127.0.0.1` を必ず付けないと `Access denied` になる。
> **罠**: bash の `-p"$PASS"` 引数展開が docker exec で崩れて `Access denied` になることがある。`docker exec -e PASS=… sh -c '… -p"$PASS"'` の **環境変数経由**で渡すと安定する。

## 4. Phase 1: 本番DBダンプ取得

```bash
TS=$(date +%Y%m%d_%H%M)

# 1-1. 本番側で .env から DB情報を確認（コンテナ内の .env が正本）
ssh kyogofuku "docker exec event_app sh -c 'grep -E ^DB_\(DATABASE\|USERNAME\|PASSWORD\)= /var/www/html/.env'"

# 1-2. パスワードは表示せず変数経由で取得して mysqldump
#   DB名は 1-1 の出力を見て固定（現在は kyogofuku_db）
PROD_DB_PASS=$(ssh kyogofuku "docker exec event_app sh -c 'grep ^DB_PASSWORD= /var/www/html/.env | cut -d= -f2-'" | tr -d '\r\n"')

ssh kyogofuku "docker exec -e PASS='$PROD_DB_PASS' shared_db sh -c '
  mysqldump -u to_murakami -p\"\$PASS\" \
    --single-transaction --default-character-set=utf8mb4 \
    --routines --triggers --no-tablespaces \
    kyogofuku_db
' 2>/tmp/dump.err | gzip > /tmp/kyogofuku_prod_${TS}.sql.gz"
unset PROD_DB_PASS

# 1-3. 念のためサイズとエラー有無確認
ssh kyogofuku "ls -lh /tmp/kyogofuku_prod_${TS}.sql.gz && \
  zcat /tmp/kyogofuku_prod_${TS}.sql.gz | head -5 && \
  echo '---stderr---' && cat /tmp/dump.err 2>/dev/null"
```

> **メモ**: `--no-tablespaces` は MariaDB10.11 でも安全。`--single-transaction` でロックを避ける。
> **目安サイズ**: 圧縮後 約22MB / 展開後 約110MB（2026-06時点）。
> **本番DBユーザー**: コンテナ内 `.env` で `DB_USERNAME=to_murakami`。`shared_db` 内ではこのユーザーが各DBに権限を持つ。

## 6. Phase 3: ローカルへインポート（localdb_prod を本番データで上書き）

```bash
TS=<Phase1と同じTS>
DUMP_DIR="/Users/to-murakami/業務データ/CC_会社/システム開発部門/京呉服平田/HP_WP/dump"

# LOCAL_DB_PASS は Phase 0 で取得済み前提（未取得なら Phase 0 のスニペット参照）

# 3-1. localdb_prod を作り直し（DROP→CREATE）
docker exec -i -e PASS="$LOCAL_DB_PASS" akioka-mysql sh -c '
  mysql -h 127.0.0.1 -u to_murakami -p"$PASS" -e "
    DROP DATABASE IF EXISTS localdb_prod;
    CREATE DATABASE localdb_prod
      CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
  "
'

# 3-2. インポート（serialized data 対策で --binary-mode=1）
docker exec -i -e PASS="$LOCAL_DB_PASS" akioka-mysql sh -c '
  mysql -h 127.0.0.1 -u to_murakami -p"$PASS" \
    --binary-mode=1 --default-character-set=utf8mb4 localdb_prod
' < "$DUMP_DIR/kyogofuku_prod_${TS}.sql"

# 3-3. インポート結果の確認
docker exec -i -e PASS="$LOCAL_DB_PASS" akioka-mysql sh -c '
  mysql -h 127.0.0.1 -u to_murakami -p"$PASS" -e "
    SELECT table_name, table_rows
    FROM information_schema.tables
    WHERE table_schema = \"localdb_prod\"
    ORDER BY table_rows DESC LIMIT 20;
  "
'
```

> **期待値（2026-06時点の参考）**: `event_utm_trackings` 約33万件、`customers` 約1,700件、`event_reservations` 約1,100件、テーブル総数 64。これより極端に少ない場合はインポート失敗を疑う。

## 7. Phase 4: 店舗マスタ補正（ローカル用に差し替え）

`docs/本番同期後_店舗マスタ補正メモ.md` のSQLを `localdb_prod` に対して実行する。
**忘れると本番Googleカレンダー / 本番LINEグループに通知が飛ぶ最重要ステップ**。

```bash
docker exec -i -e PASS="$LOCAL_DB_PASS" akioka-mysql sh -c '
  mysql -h 127.0.0.1 -u to_murakami -p"$PASS" localdb_prod
' <<'SQL'
UPDATE shops
SET
  google_calendar_id = 'fd488d9a46c6581a5653a642b67064cd491f2d4eeaf17aa675a625e62df99882@group.calendar.google.com',
  line_group_id      = 'C4bbc8f222d645a6aa65506598b29b020'
WHERE id IN (1, 2);

UPDATE shops
SET
  google_calendar_id = NULL,
  line_group_id      = 'C4bbc8f222d645a6aa65506598b29b020'
WHERE id IN (3, 4, 5);

SELECT id, name, google_calendar_id, line_group_id FROM shops ORDER BY id;
SQL
```

> **店名の文字化け**: コンテナの `mysql` クライアントは出力ロケールが C のため日本語が `???` 表示になることがあるが、データ自体は正常。Laravel 側（Phase 6-2）で確認すれば日本語で見える。

## 8. Phase 5: 画像ストレージ同期

`event_app` コンテナはストレージをマウントしておらず、コンテナ内 `/var/www/html/storage/app/public/` が正本（2026-06時点で 62MB / 249ファイル）。
ホスト側 `/srv/.../app/storage/app/public/` は古いので**使わない**。

```bash
APP_DIR="/Users/to-murakami/業務データ/CC_会社/システム開発部門/京呉服平田/HP_WP/kyogofuku-app"
DAY=$(date +%Y%m%d_%H%M)

# 5-1. VPS上で docker cp（コンテナ → /tmp）
ssh kyogofuku "rm -rf /tmp/kyogofuku_storage_${DAY} && \
  docker cp event_app:/var/www/html/storage/app/public /tmp/kyogofuku_storage_${DAY} && \
  du -sh /tmp/kyogofuku_storage_${DAY}"

# 5-2. rsync で取得（差分のみ、ローカルにしかないファイルは削除して本番と完全一致）
rsync -avz --delete --stats \
  "kyogofuku:/tmp/kyogofuku_storage_${DAY}/" \
  "$APP_DIR/storage/app/public/"

# 5-3. 本番側の一時ディレクトリ削除
ssh kyogofuku "rm -rf /tmp/kyogofuku_storage_${DAY}"

# 5-4. シンボリックリンク (public/storage) 確認
cd "$APP_DIR"
[ -L public/storage ] && echo "OK: public/storage はシンボリックリンク" \
  || /opt/homebrew/opt/php@8.2/bin/php artisan storage:link
```

> **`--delete` の判断**: 完全に本番と一致させたいなら付ける。ローカルで作ったテスト画像を温存したいなら外す。
> **マウント確認コマンド**: `ssh kyogofuku "docker inspect event_app --format '{{ range .Mounts }}{{ .Source }} -> {{ .Destination }}{{ println }}{{ end }}'"`（現状は空＝マウント無し）。

## 10. ロールバック手順

`localdb_prod` を常用する運用に切り替わったため、**ロールバック = Phase 0-1 のバックアップから localdb_prod を戻す**。

```bash
APP_DIR="/Users/to-murakami/業務データ/CC_会社/システム開発部門/京呉服平田/HP_WP/kyogofuku-app"
DUMP_DIR="/Users/to-murakami/業務データ/CC_会社/システム開発部門/京呉服平田/HP_WP/dump"
PHP=/opt/homebrew/opt/php@8.2/bin/php

# A. DB を pre_sync バックアップから戻す（Phase 0-1 を取っていた場合のみ）
docker exec -i -e PASS="$LOCAL_DB_PASS" akioka-mysql sh -c '
  mysql -h 127.0.0.1 -u to_murakami -p"$PASS" -e "
    DROP DATABASE IF EXISTS localdb_prod;
    CREATE DATABASE localdb_prod CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
  "
'
docker exec -i -e PASS="$LOCAL_DB_PASS" akioka-mysql sh -c '
  mysql -h 127.0.0.1 -u to_murakami -p"$PASS" --binary-mode=1 localdb_prod
' < "$DUMP_DIR/local_localdb_prod_<TS>_pre_sync.sql"

# B. 画像を pre_sync スナップショットに戻す（必要時のみ）
cd "$APP_DIR"
rm -rf storage/app/public
mkdir -p storage/app/public
tar xzf "$DUMP_DIR/local_storage_<TS>_pre_sync.tgz" -C "$APP_DIR"

# C. キャッシュクリア
$PHP artisan config:clear
```

> **Phase 0-1 のバックアップを取っていなかった場合**は元の状態には戻せない。再度本番から取り直す（同期は何度でも安全に実行できるので、それでも実害は小さい）。

## 11. リスクと注意点

| リスク | 対策 |
|---|---|
| 本番DB ロック発生 | `--single-transaction` で防止。実行は混雑時間帯を避ける |
| **Phase 4 の補正忘れ → 本番Googleカレンダーへ書き込み** | Phase 6-2 で shops を必ず確認。岡山店・城東店のIDがローカル用 (`fd488d9a…`) になっていなければ作業中止 |
| ダンプサイズが大きい（event_utm_trackings 33万件等） | gzip圧縮で転送。所要時間目安は数分。展開後 約110MB |
| 画像が壊れる/欠落 | `Phase 0-2` のtarで戻せる。`rsync --delete` を使う場合は特に注意 |
| `config:cache` を実行 → LINE通知が壊れる | キャッシュ操作は **`config:clear` のみ** とする（既知の罠） |
| `to_murakami@localhost` 拒否 | `akioka-mysql` コンテナ内でも `-h 127.0.0.1` を必ず付ける |
| bashのパスワード引数展開で `Access denied` | `docker exec -e PASS=… sh -c '… -p"$PASS"'` の **環境変数経由**で渡す |
| `php artisan` が `vendor/autoload.php` で fatal | システム `php` (8.1) ではなく `/opt/homebrew/opt/php@8.2/bin/php` を使う |
