> **要点：**
> 1. 紹介者特典＝ステージ別クーポン → **ポイント還元（被紹介者の成約金額×ステージ%）**。被紹介者特典＝5,000円OFFクーポン → **成約時に固定ポイント（初期10,000pt）**。
> 2. 紹介者・被紹介者は **共通のポイント残高**を持ち、**500円単位でギフトカードに引換**（キャッシュバックは不採用）。ギフトカード発行は**店舗対応**、システムは「**発行済み**」ボタンでポイント減算。

> 4. `stage_coupon_grants` と被紹介者クーポン配布フローは **廃止**。クーポンは「管理画面からの任意配布」用途のみ存続（併用可否フラグ追加）。

## 1. 背景・要件

### 1.1 ユーザー要望（要約）

公式LINEを有効活用するため、**友達紹介プログラム**を導入する。

- 紹介者が知人に公式LINEを紹介し、その知人が**成約**に至った場合、紹介者のステージが上がる
- ステージに応じて自動でクーポンが配布される
- 公式LINE上では「友達紹介」「マイステージ確認」「マイポイント・ギフト」「顧客詳細（マイページ）」を提供（確定版・§1.2 N）
- クーポンは**マスタで一元管理**し、画像付き Flex Message で配布、ユーザーは「受け取る」ボタンで保有状態化
- クーポンの**使用処理は管理画面からのみ**（LIFFは表示専用）

### 1.2 設計確定事項（2026-06-25 確定・C-1〜C-12）

| # | 論点 | 確定方針 |
|---|------|----------|
| A | 紹介の利用条件 | **①LINE連携 ②顧客登録済 ③成約済** の3条件すべて。成約金額の閾値なし（`referral_codes` は成約済顧客のみ有効）|
| B | ステージ名称 | ブロンズ / シルバー / ゴールド / プラチナ（名称確定） |
| C | ステージ判定人数（可変） | 成立(matured)人数で **ブロンズ0〜3 / シルバー4〜6 / ゴールド7〜10 / プラチナ11+**。**管理画面で変更可** |
| D | 紹介者特典 | **ポイント還元＝被紹介者の成約金額 × ステージ別還元率**。還元率初期 **3 / 4 / 5 / 10%**（管理画面で可変） |
| E | 被紹介者特典 | 成約時に **固定ポイント（初期10,000pt・管理画面で可変）**。旧5,000円OFFクーポンは廃止 |
| F | 特典の引換 | 紹介者・被紹介者とも **共通残高から500円単位でギフトカード引換**（単位は管理画面で可変）。**キャッシュバックは不採用** |
| G | ギフトカード発行 | **店舗で発行**し、システムは「**発行済み**」ボタンで**ポイント減算**。誤発行はキャンセルで返還。将来は管理画面発行も検討 |
| H | ポイント計算の基準額 | **税抜・割引後の実成約額**（`contracts` の成約金額列）。1ポイント＝1円。ポイント有効期限なし（無期限） |
| I | 特典付与のタイミング | **成約1ヶ月後（クーリングオフ後）にバッチで確定**。起算日＝契約確定日（成約日） |
| J | 紹介トラッキング方式 | LIFF経由（`?ref=XXXX`）。紹介者名は伏せる（「お知り合いの方からのご紹介で…」） |
| K | 紹介の有効期限 | 友達追加から **6ヶ月** で `expired` |
| L | 自己紹介・既存顧客防止 | line_user_id 一致や既存customer は `rejected` で記録 |
| M | クーポン（任意配布用） | ステージ別配布は廃止。**管理画面からの任意配布**用途のみ存続。**発行時に併用可否を登録**。使用は管理画面の「使用」ボタン |
| N | リッチメニュー | 4項目：友達紹介 / マイステージ / マイポイント・ギフト / **顧客詳細（マイページ：顧客情報・成約・前撮り日の表示専用）** |

### 1.3 スコープ外（将来拡張）

- 紹介者・被紹介者への昇格／付与通知（Push）：**今回スコープに含む**（§4参照）
- 定期Push通知（シルバー以上向け）：**今回スコープに含まない**。Phase 6で別途検討
- ギフトカードの**管理画面からの発行・送付**：当面はスタッフが店舗発行＋「発行済み」記録。将来拡張

### 3.2 各テーブル定義（確定版）

#### ① `referral_codes`
```sql
- id
- customer_id (FK customers, unique, cascadeOnDelete)
- code (string(8), unique)            -- 大文字英数字
- created_at / updated_at
-- ※ 発行は「成約済顧客」のみ（利用条件 §1.2 A）。未成約顧客には紹介URLを出さない。
```

#### ② `referrals`
```sql
- id
- referrer_customer_id (FK customers, cascadeOnDelete)
- referred_line_user_id (string)      -- LIFF経由で取得した友達追加者のLINE user_id
- referred_customer_id (FK customers, nullable)  -- 後でcustomer作成時に後埋め
- status (enum: linked/contracted/matured/expired/rejected) default 'linked'
    -- linked    : LINE紐付け完了（紹介成立待ち）
    -- contracted: 被紹介者が成約（仮確定。contracted_at 記録。まだ特典付与しない）
    -- matured   : 成約から1ヶ月経過し確定（このタイミングで特典付与＝ポイント）
    -- expired   : 6ヶ月経過しても成約なし
    -- rejected  : 自己紹介・既存顧客・重複等で無効化
- contract_id (FK contracts, nullable)
- contracted_at (timestamp, nullable) -- 成約検知時刻（matured判定の起算）
- matured_at (timestamp, nullable)    -- 確定（特典付与）時刻
- expires_at (timestamp)              -- linked時刻 + 6ヶ月
- created_at / updated_at

INDEX:
- unique (referrer_customer_id, referred_line_user_id)
- index (referred_line_user_id)
- index (status, expires_at)          -- 期限切れバッチ用
- index (status, contracted_at)       -- matureバッチ用（contracted_at+1ヶ月）
```

#### ③ `customer_stages`
```sql
- id
- customer_id (FK customers, unique, cascadeOnDelete)
- stage (enum: bronze/silver/gold/platinum) default 'bronze'
- matured_referrals_count (unsignedInteger) default 0  -- 成立(matured)した紹介数
- last_evaluated_at (timestamp, nullable)
- created_at / updated_at
```

#### ④ `stage_settings`（★新規：管理画面で可変）
```sql
- id
- stage (enum: bronze/silver/gold/platinum, unique)
- min_referrals (unsignedInteger)     -- このステージになる最小成立人数（例 bronze=0, silver=4, gold=7, platinum=11）
- reward_rate_percent (decimal(5,2))  -- 還元率%（初期 bronze=3, silver=4, gold=5, platinum=10）
- created_at / updated_at
-- ※ 初期値は seeder で投入。判定は min_referrals の昇順で「該当する最上位ステージ」を採用。
```

#### ⑤ `referral_points`（★新規：ポイント残高・紹介者/被紹介者 共通）
```sql
- id
- customer_id (FK customers, unique, cascadeOnDelete)
- balance (integer) default 0         -- 現在の保有ポイント（1pt=1円）
- created_at / updated_at
-- ※ 残高は point_ledger の合計と一致させる（更新は必ず台帳と同一トランザクション）。
```

#### ⑥ `point_ledger`（★新規：ポイント増減台帳）
```sql
- id
- customer_id (FK customers, cascadeOnDelete)
- amount (integer)                    -- +獲得 / -引換・調整
- type (enum: referrer_reward/referred_bonus/gift_card_redeem/gift_card_cancel_refund/adjust)
    -- referrer_reward         : 紹介者へ成約金額×%付与
    -- referred_bonus          : 被紹介者へ固定pt付与
    -- gift_card_redeem        : ギフトカード引換でマイナス
    -- gift_card_cancel_refund : ギフトカード取消で返還（プラス）
    -- adjust                  : 手動調整
- referral_id (FK referrals, nullable)   -- 付与の根拠
- gift_card_id (FK gift_cards, nullable) -- 引換/返還の根拠
- note (string, nullable)
- created_at / updated_at

INDEX:
- index (customer_id, created_at)
```

#### ⑦ `gift_cards`（★新規：ギフトカード発行履歴）
```sql
- id
- customer_id (FK customers, cascadeOnDelete)
- amount (unsignedInteger)            -- 引換額（500円単位）
- status (enum: issued/canceled) default 'issued'
    -- issued   : 店舗で発行済（ポイント減算済）
    -- canceled : 誤発行等で取消（ポイント返還済）
- issued_by_user_id (FK users, nullable)  -- 「発行済み」ボタンを押したスタッフ
- issued_shop_id (FK shops, nullable)
- issued_at (timestamp)
- canceled_at (timestamp, nullable)
- created_at / updated_at

INDEX:
- index (customer_id, status)
-- ※ 実際の券種・送付は店舗運用（システム外）。本テーブルは発行記録とポイント整合のためのもの。
```

#### ⑧ `referral_settings`（key-value）
```sql
- id
- key (string, unique)
    -- referred_bonus_points           : 被紹介者特典の固定pt（初期 10000）
    -- gift_card_unit                  : ギフトカード引換単位（初期 500）
    -- referral_expire_months          : 紹介有効期限（月数、初期 6）
    -- maturation_months               : 成約→確定までの月数（初期 1）
    -- referral_message_template       : 被紹介者へのお礼テキスト
    -- referrer_promotion_notify_text_{silver|gold|platinum} : 昇格通知文面
- value (text)
- created_at / updated_at
-- ※ 還元率・人数閾値は stage_settings 側（テーブル）で管理。
```

#### ⑨ `coupons`（任意配布クーポン・マスタ／改訂）
```sql
- id
- name / description / image_path / thumbnail_path / terms_text
- discount_type (enum: fixed/rate) / discount_value
- valid_days / valid_until_fixed
- combinable (boolean) default false   -- ★併用可否（true=併用可）
- status (enum: active/inactive/archived) default 'active'
- created_at / updated_at
-- ※ 被紹介者特典としては使わない。管理画面からの任意配布専用。
```

#### ⑩ `customer_coupons`（任意配布クーポンの保有／改訂）
```sql
- id
- customer_id (FK customers, cascadeOnDelete)   -- ★NOT NULL のまま（nullable化は見送り＝C-12）
- coupon_id (FK coupons, restrictOnDelete)
- status (enum: held/used/expired) default 'held'
- used_at / used_by_user_id (FK users) / used_shop_id (FK shops)
- created_at / updated_at
-- ※ 受取postback方式は廃止。配布＝held で作成し、管理画面の「使用」ボタンで used。
```

## 4. 処理フロー

### 4.1 紹介コード発行

- `Customer` 作成時の Observer で `referral_codes` を1件作成（重複しないコードをリトライ生成）
- 既存顧客への一括発行は Artisan コマンド `php artisan referral:backfill-codes` を用意

### 4.2 紹介リンク生成（紹介者側）

リッチメニュー「友達を紹介する」→ `https://liff.line.me/{LINE_LIFF_ID}/referral` 起動

LIFF画面で以下を表示：
- 紹介URL: `https://liff.line.me/{LINE_LIFF_ID}/referral?ref={code}`
- QRコード（同URLを埋め込み）
- 「LINEで共有」ボタン（`liff.shareTargetPicker`）
- 紹介済み一覧（成立件数 / 保留件数のみ。被紹介者の個人情報は表示しない）

### 4.3 紹介経由の友達追加〜紐付け

```
被紹介者が紹介URLタップ
  ↓
LIFF起動（?ref=XXXX を保持）
  ↓
[判定A] LINE Login の IDトークン取得
  ↓
[判定B] 公式LINEを友達追加していない場合
  → 「友達追加」ボタンを表示（既存の add_friend_url を流用）
  → 友達追加後、LIFFに戻る
  ↓
[判定C] 紹介コード(ref) を referral_codes から検索 → referrer_customer_id 取得
  ↓
[判定D] 自己紹介チェック：referrer のLINE紐付けと現在のLINE user_id が同一 → reject
  ↓
[判定E] 既存紹介チェック：referrals に (referrer, referred_line_user_id) 存在 → 既存返却
  ↓
referrals INSERT (status='linked', expires_at=now+6mo)
  ↓
お礼テキストPush：referral_settings.referral_message_template
  （特典は「成約後にポイント付与」する旨を案内。クーポン配布Pushは行わない）
```

### 4.4 成約検知（仮確定）

```
管理画面で contracts.status を '確定' に更新（被紹介者Bの契約）
  ↓
ContractObserver::created()/updated() が検知（idempotent）
  ↓
referred_customer_id=B かつ status='linked' の referrals を取得
  ↓
status='contracted'（仮）, contract_id, contracted_at=now に更新
  ※ この時点では特典付与・ステージ評価は行わない（1ヶ月後に持ち越し）
```

### 4.5 確定バッチ（成約1ヶ月後）〜ポイント付与〜ステージ昇格

```
php artisan referral:mature（日次cron）
  ↓
status='contracted' かつ contracted_at + maturation_months ≤ now の referrals を抽出
  （途中で契約キャンセルされていれば対象外）
  ↓
referrals を status='matured', matured_at=now に更新
  ↓
【① 紹介者A】
  ├ StageEvaluator(A)：matured件数を再カウント → stage_settings の min_referrals で判定 → 昇格 or 据置
  ├ 昇格時：customer_stages(A).stage 更新 ＋ 昇格通知Push（テキスト）
  └ ポイント付与：付与pt = Bの成約金額(税抜・割引後) × Aの現ステージ reward_rate_percent
       → referral_points(A).balance 加算 ＋ point_ledger(type='referrer_reward', referral_id) INSERT
  ↓
【② 被紹介者B】
  └ 固定ポイント付与：referral_settings.referred_bonus_points（初期10,000）
       → referral_points(B).balance 加算 ＋ point_ledger(type='referred_bonus', referral_id) INSERT
```

### 4.6 ギフトカード引換（店舗対応）

```
顧客が来店し、ギフトカード引換を申し出（残高はマイポイントLIFFで確認可）
  ↓
スタッフが管理画面で引換額（500円単位・残高以内）を指定し、店舗でギフトカードを発行・手渡し
  ↓
「発行済み」ボタン押下
  ↓
gift_cards INSERT (status='issued', amount, issued_by_user_id, issued_shop_id)
  ↓
referral_points 減算 ＋ point_ledger(type='gift_card_redeem', gift_card_id) INSERT
  ↓
（誤発行時）「キャンセル」→ gift_cards.status='canceled' ＋ point_ledger(type='gift_card_cancel_refund') で返還
```

### 4.7 期限切れバッチ

- `php artisan referral:expire` を日次cron実行
  - `referrals` で `status='linked' && expires_at < now` を `expired` に更新（成立せず期限切れ）

## 9. リスク・留意点

| 区分 | 内容 | 対策 |
|---|---|---|
| 個人情報 | 紹介者・被紹介者の相互開示はトラブル源 | LIFF表示は件数のみ・名前は伏字 |
| 不正利用 | 自己紹介・複数アカウント悪用 | line_user_id 同一拒否・1紹介者×1被紹介者でユニーク |
| Push通信費 | 月200通超で課金 | 配布前に件数プレビュー必須 / 配布履歴を管理画面で集計 |
| 既存顧客の重複検知 | 被紹介者の電話/メールが既存customers と一致 | 紹介成立時に既存顧客と判定された場合は `referrals.status='rejected'` |
| 景品表示法 | 過度な特典は規制対象 | 値引き額の上限を社内で決定（要法務確認） |
| クーポン無限増殖 | 同一マスタを何度も配布 | `customer_coupons` の `unique(customer_id, coupon_id, status)` で `offered`/`held` 重複防止 |
| LINE側仕様変更 | Messaging API / LIFF SDK 更新 | バージョンを `composer.json` / `package.json` で固定 |
| 紹介URL拡散 | 第三者への流出 | コードは8桁ランダムで衝突回避、必要なら再発行UIを設ける（Phase外） |

## 付録A：ステージ設定の初期値（`stage_settings` seeder・管理画面で可変）

| ステージ | min_referrals（最小成立人数） | reward_rate_percent（還元率） | 帯の目安 |
