# LINE公式アカウント リッチメニュー作成手順（2026-06-05）

[20260605_LINE紹介機能_実装計画.md](./20260605_LINE紹介機能_実装計画.md) の Phase 4 で本番反映するリッチメニューの**作成・登録手順**をまとめる。デザイン作業は村上さん担当、本書はデザイン要件と登録作業の説明にフォーカスする。

---

## 1. 全体像

リッチメニューの設定には**2つの方法**がある。

| 方式 | 特徴 | 本プロジェクトでの使用 |
|---|---|---|
| **A. LINE Official Account Manager（管理画面・GUI）** | ブラウザ上で画像アップ→領域指定→アクション設定。非エンジニアでも完結 | ❌ 採用しない |
| **B. Messaging API（プログラム経由）** | JSON定義で領域・アクションを管理。バージョン管理・再現性が高い | ✅ **採用** |

**B方式を採用する理由**：
- リッチメニューの構成（領域・LIFF URL）が `storage/app/line/rich_menu.json` で Git 管理できる
- ステージング/本番の二環境で差分なく再現できる
- LIFF IDなど環境固有値を `.env` から動的に流し込める
- 将来「ステージ別リッチメニュー切替」など拡張する際、Aだと不可

ただし、**最初の動作確認段階のみ A方式で素早く検証**するのは有効。本書では両方記載する。

## 2. リッチメニュー画像の仕様

### 2.1 サイズ（LINE公式仕様）

| テンプレート | 画像サイズ（px） | 領域数 |
|---|---|---|
| **大・3×2マス（今回採用）** | **2500 × 1686** | 6マス |
| 大・2×2マス | 2500 × 1686 | 4マス |
| 大・1×2マス | 2500 × 1686 | 2マス |
| 小・3×1マス | 2500 × 843 | 3マス |
| 小・2×1マス | 2500 × 843 | 2マス |

> 今回は機能数が6つ（友達紹介・マイステージ・保有クーポン・イベント予約・問い合わせ・FAQ）のため **大・3×2マス（2500×1686）** を採用。

### 2.2 ファイル要件

| 項目 | 仕様 |
|---|---|
| フォーマット | **JPG / JPEG / PNG** |
| カラーモード | RGB（CMYK不可） |
| ファイルサイズ | **1MB以下** |
| アスペクト比 | 縦横比固定（リサイズ不可。指定サイズちょうどで作成） |
| 解像度 | 72 dpi 推奨（画面表示用） |

### 2.3 領域分割（2500×1686, 3×2マス）

```
┌────────────┬────────────┬────────────┐
│  ① 友達紹介  │ ② マイステージ│ ③ 保有クーポン│
│            │            │            │
│  833×843   │  834×843   │  833×843   │
│  (0, 0)    │ (833, 0)   │(1667, 0)   │
├────────────┼────────────┼────────────┤
│ ④ イベント予約│ ⑤ 問い合わせ │   ⑥ FAQ    │
│            │            │            │
│  833×843   │  834×843   │  833×843   │
│ (0, 843)   │(833, 843)  │(1667, 843) │
└────────────┴────────────┴────────────┘
```

**各マスの座標一覧**（後述のJSONと対応）：

| # | 機能 | x | y | width | height |
|---|---|---|---|---|---|
| ① | 友達紹介 | 0 | 0 | 833 | 843 |
| ② | マイステージ | 833 | 0 | 834 | 843 |
| ③ | 保有クーポン | 1667 | 0 | 833 | 843 |
| ④ | イベント予約 | 0 | 843 | 833 | 843 |
| ⑤ | 問い合わせ | 833 | 843 | 834 | 843 |
| ⑥ | FAQ | 1667 | 843 | 833 | 843 |

> **注意**：2500 ÷ 3 = 833.33… のため、中央列だけ幅 834 にして合計が2500ちょうどになるよう調整している。

## 3. デザインガイドライン（村上さん向け）

### 3.1 推奨レイアウト

各マス内（833×843 または 834×843）：

```
┌───────────────────────┐
│  ↑ 上下マージン 80px  │
│  ┌─────────────┐      │
│  │             │      │
│  │   アイコン   │  ←  300×300px 程度
│  │             │      │
│  └─────────────┘      │
│        ↑ 40px         │
│  ┌─────────────┐      │
│  │  ラベル文字  │  ←  60〜80pt 程度の太字
│  └─────────────┘      │
│  ↓ 下マージン 80px    │
└───────────────────────┘
```

### 3.2 デザイン上の注意点

| 項目 | 推奨 |
|---|---|
| 区切り線 | 各マスの境界に細い線（2〜4px）を入れると押せることが伝わりやすい |
| 余白 | マスの端から60〜100pxは余白を確保（指で押すとき視認性UP） |
| 文字サイズ | スマホ画面ではリッチメニューは画面横幅まで縮小される。**フォントは最低60pt、推奨80pt以上の太字** |
| 色のコントラスト | 背景と文字のコントラスト比 4.5:1 以上（アクセシビリティ） |
| アイコン | シルエットで意味が伝わるもの推奨（ハート＝紹介、星＝ステージ、チケット＝クーポン等） |
| ブランドカラー | 京呉服平田のコーポレートカラー（要確認）を1〜2色アクセントに |
| タップ可能感 | フラットすぎる単色塗りつぶしより、わずかなグラデーション・影で「ボタン感」を出す |

### 3.3 デザインに使えるツール

- **Figma**（推奨）：2500×1686のアートボードを作成し、6分割。書き出しはPNG 1x。
- **Canva**：「カスタムサイズ」で 2500×1686 を指定。テンプレートも豊富。
- **Adobe XD / Illustrator / Photoshop**：解像度設定に注意（72dpi、RGB）。

### 3.4 デザイン提出時の確認チェックリスト

- [ ] サイズが 2500×1686 ちょうど
- [ ] PNG（または JPG）で書き出し
- [ ] ファイルサイズが 1MB以下
- [ ] カラーモードが RGB
- [ ] 6マスの境界が視覚的に分かる
- [ ] 各マスのラベル文字がスマホでも読める大きさ
- [ ] アイコンと機能名が一致している

## 4. リッチメニュー定義 JSON

`storage/app/line/rich_menu.json` に配置する定義ファイル。

```json
{
  "size": {
    "width": 2500,
    "height": 1686
  },
  "selected": true,
  "name": "kyogofuku_default_2026_06",
  "chatBarText": "メニュー",
  "areas": [
    {
      "bounds": { "x": 0, "y": 0, "width": 833, "height": 843 },
      "action": {
        "type": "uri",
        "label": "友達紹介",
        "uri": "https://liff.line.me/{LIFF_ID}/referral"
      }
    },
    {
      "bounds": { "x": 833, "y": 0, "width": 834, "height": 843 },
      "action": {
        "type": "uri",
        "label": "マイステージ",
        "uri": "https://liff.line.me/{LIFF_ID}/my-stage"
      }
    },
    {
      "bounds": { "x": 1667, "y": 0, "width": 833, "height": 843 },
      "action": {
        "type": "uri",
        "label": "保有クーポン",
        "uri": "https://liff.line.me/{LIFF_ID}/my-coupons"
      }
    },
    {
      "bounds": { "x": 0, "y": 843, "width": 833, "height": 843 },
      "action": {
        "type": "uri",
        "label": "イベント予約",
        "uri": "https://fukui.kyogofuku-hirata.jp/events"
      }
    },
    {
      "bounds": { "x": 833, "y": 843, "width": 834, "height": 843 },
      "action": {
        "type": "message",
        "label": "問い合わせ",
        "text": "店舗に問い合わせ"
      }
    },
    {
      "bounds": { "x": 1667, "y": 843, "width": 833, "height": 843 },
      "action": {
        "type": "uri",
        "label": "FAQ",
        "uri": "https://fukui.kyogofuku-hirata.jp/faq"
      }
    }
  ]
}
```

### 主要パラメータ

| パラメータ | 説明 |
|---|---|
| `size` | 画像サイズ（必ず実画像と一致） |
| `selected` | 友達追加時にデフォルト表示するか（trueで自動表示） |
| `name` | リッチメニュー管理用名称（社内識別用、ユーザーには見えない） |
| `chatBarText` | トーク画面下部のメニューバーに表示される文字（最大14文字） |
| `areas` | 各マスの位置とアクション定義 |

### アクションタイプ

| type | 用途 | 設定 |
|---|---|---|
| `uri` | URL/LIFF を開く | `uri` 必須 |
| `message` | 指定文字列をユーザー発言として送信 | `text` 必須 |
| `postback` | バックエンドへ data 送信 | `data` 必須 |
| `richmenuswitch` | 別リッチメニューに切替（拡張用） | `richMenuAliasId`, `data` |

## 5. 登録手順（B方式：Artisanコマンド）

### 5.1 事前準備

1. **画像ファイルを配置**
   ```
   storage/app/line/rich_menu.png
   ```
   ※ファイル名固定。差し替え時は同名で上書き。

2. **定義JSONを配置**
   ```
   storage/app/line/rich_menu.json
   ```
   ※`{LIFF_ID}` は `.env` の `LINE_LIFF_ID` で置換される（コマンド内で実装）。

3. **環境変数を確認**（`.env`）
   ```
   LINE_MESSAGING_CHANNEL_ACCESS_TOKEN=xxx
   LINE_LIFF_ID=xxx
   ```

### 5.2 コマンド実行

```bash
# 既存リッチメニュー一覧確認
php artisan line:rich-menu:list

# 新規登録 + 画像アップロード + デフォルト設定
php artisan line:rich-menu:register

# 既存リッチメニューを削除
php artisan line:rich-menu:delete {richMenuId}
```

### 5.3 コマンド内部処理（参考：実装は Phase 4 で行う）

```php
// 1. リッチメニュー作成
POST https://api.line.me/v2/bot/richmenu
Header: Authorization: Bearer {ACCESS_TOKEN}
Body: rich_menu.json の中身（LIFF_ID置換済み）
→ richMenuId が返る

// 2. 画像アップロード
POST https://api-data.line.me/v2/bot/richmenu/{richMenuId}/content
Header: Content-Type: image/png
Body: rich_menu.png のバイナリ

// 3. 全友達のデフォルトに設定
POST https://api.line.me/v2/bot/user/all/richmenu/{richMenuId}

// 4. 旧リッチメニュー削除（任意）
DELETE https://api.line.me/v2/bot/richmenu/{oldRichMenuId}
```

### 5.4 デプロイフロー

```
ローカルで画像・JSON更新
  ↓
ステージング環境でコマンド実行 → 実機確認
  ↓
本番環境にデプロイ（git pull）
  ↓
本番でコマンド実行
  ↓
公式LINEを開いて反映確認（数分かかる場合あり）
```

## 6. 登録手順（A方式：LINE Official Account Manager・GUI）

設計確認段階や緊急対応で使う場合の手順。**通常運用では使わない**。

### 6.1 アクセス

1. https://manager.line.biz/ にログイン
2. 京呉服平田の公式アカウントを選択
3. 左メニュー「**トークルーム管理 > リッチメニュー**」

### 6.2 作成手順

1. 右上「**作成**」ボタン
2. **タイトル**（社内識別用）：例「kyogofuku_default_2026_06」
3. **表示期間**：開始日時のみ指定（終了は無期限なら空欄）
4. **コンテンツ設定**
   - テンプレート：「大（2500×1686）の3×2マス」を選択
   - 「**画像を選択**」で `rich_menu.png` をアップロード
5. **アクション設定**：各マスをクリックして以下を設定

| マス | タイプ | 設定内容 |
|---|---|---|
| ① 友達紹介 | リンク | URL: `https://liff.line.me/{LIFF_ID}/referral` |
| ② マイステージ | リンク | URL: `https://liff.line.me/{LIFF_ID}/my-stage` |
| ③ 保有クーポン | リンク | URL: `https://liff.line.me/{LIFF_ID}/my-coupons` |
| ④ イベント予約 | リンク | URL: `https://fukui.kyogofuku-hirata.jp/events` |
| ⑤ 問い合わせ | テキスト | テキスト: `店舗に問い合わせ` |
| ⑥ FAQ | リンク | URL: `https://fukui.kyogofuku-hirata.jp/faq` |

6. **メニューバーのテキスト**：`メニュー`
7. **メニューのデフォルト表示**：オン
8. 右上「**保存**」

### 6.3 注意事項

- A方式で保存したリッチメニューは Messaging API からも見える
- B方式（Artisanコマンド）で上書き登録すると、A方式で作ったものは削除される
- **A方式とB方式の併用は混乱の元**なので、本格運用後はB方式のみに統一する

## 7. 動作確認手順

### 7.1 実機確認

1. iPhone / Android で公式LINEを開く
2. トーク画面下部にリッチメニューが表示されることを確認
3. 各マスをタップして、想定動作（LIFF起動・テキスト送信）が行われることを確認
4. **チェックリスト**
   - [ ] ① タップで紹介LIFFが開く
   - [ ] ② タップでマイステージLIFFが開く
   - [ ] ③ タップで保有クーポンLIFFが開く
   - [ ] ④ タップでイベント予約ページが開く
   - [ ] ⑤ タップで「店舗に問い合わせ」とユーザー発言が投稿される
   - [ ] ⑥ タップでFAQページが開く
   - [ ] チャットバーに「メニュー」と表示される

### 7.2 反映タイミング

- 新規友達追加：即時反映
- 既存友達：**最大1時間程度**キャッシュが残る場合あり
- 強制反映：LINEアプリを完全終了→再起動

### 7.3 反映されない場合

| 症状 | 原因 | 対処 |
|---|---|---|
| リッチメニュー自体が出ない | デフォルト設定漏れ | `POST /v2/bot/user/all/richmenu/{id}` を再実行 |
| 一部マスが反応しない | 領域座標のズレ | JSON の `bounds` を再確認 |
| LIFFが開かない | LIFF ID 誤り / LIFF未公開 | LINE Developers で LIFF設定確認 |
| 画像が古いまま | LINEアプリ側キャッシュ | アプリ再起動・1時間待機 |

## 8. 更新・差し替え運用

### 8.1 デザインのみ差し替え（同じ機能構成）

1. 新画像を `rich_menu.png` で上書き
2. `php artisan line:rich-menu:register` 実行
   - 内部で新しい `richMenuId` が発行される
   - 旧リッチメニューを削除
   - 全友達のデフォルトを新しいIDに切替

### 8.2 構成変更（マス数・配置変更）

1. `rich_menu.json` を編集（`size` / `areas`）
2. 新画像を `rich_menu.png` で上書き
3. `php artisan line:rich-menu:register` 実行

### 8.3 完全削除（メニューを非表示にしたい）

```bash
# デフォルト設定解除
DELETE https://api.line.me/v2/bot/user/all/richmenu

# リッチメニュー本体削除
php artisan line:rich-menu:delete {richMenuId}
```

## 9. 拡張：ステージ別リッチメニュー切替（将来構想）

将来「シルバー以上の会員には専用メニューを表示」したい場合の構成例。**今回スコープ外**だが将来の拡張余地として記載。

```
[全員向け]     [シルバー以上向け]
├ 友達紹介     ├ 友達紹介
├ マイステージ ├ マイステージ
├ 保有クーポン ├ 保有クーポン
├ イベント予約 ├ 限定イベント予約  ← 違う
├ 問い合わせ   ├ VIP問い合わせ      ← 違う
└ FAQ          └ ステージ特典案内   ← 違う
```

実装方針：
- 2種類のリッチメニューを登録
- ステージ昇格時 / 降格時に該当ユーザーのリッチメニューを切替（`POST /v2/bot/user/{userId}/richmenu/{richMenuId}`）
- 友達追加時はデフォルト（全員向け）を割当
