  • 本番はDocker構成でLaravelスケジューラを使わないため、VPSホスト側のcronで起動する（設定手順：docs/CRON_SETUP_REFERRAL_MATURE.md）。いずれも冪等（二重付与しない）。

11. テスト方針

✅ 結論 機能（ロジック）テストはほぼ全部ローカルの PHPUnit で完結し、LINE 実機テストも本番デプロイは不要（ngrok でローカルを HTTPS 公開すれば実機確認できる）。本リポジトリは Push を Http::fake() で差し替えられ、Webhook 署名をテスト内生成できる作りのため、自動テストの守備範囲が広い。

11.1 テスト区分（2軸）

テスト種別必要環境本番デプロイ主目的
機能（ロジック）テストローカル PHPUnit のみ不要ポイント計算・ステージ判定・バッチ・引換・Observer 等

11.2 ローカルで完結する自動テスト（PHPUnit）

11.3 ローカル実機相当テスト（ngrok・本番デプロイ不要）

LINE は Webhook/LIFF に HTTPS 公開 URL を要求するため、ngrok で localhost を公開する（手順は docs/LINE_MESSAGING_TESTING.md。本プロジェクトの APP_URL も ngrok を使用中）。

  1. ngrok http 8000 で公開URLを発行（現在：https://unnagging-needingly-archimedes.ngrok-free.dev）
  2. .env の APP_URL／Messaging の Webhook URL／LIFF Endpoint／Login Callback を全てその ngrok URL に揃える → php artisan config:clear
  3. テスト用 LINE アカウントで「友達追加 → 紹介URL → LIFF紐付け →（管理画面で成約登録）→（1ヶ月後相当で）ポイント付与 → ギフトカード引換」を実機で一気通し
⚠️ ngrok 利用時の注意 無料URLは再起動で変わるため、そのたびに LINE コンソール（Webhook/LIFF/Callback）の再登録が必要。referral 用に LINE Login チャネル＋LIFFアプリの登録が要る。常設URLが欲しい場合は ngrok 有料 or ステージング VPS を検討。

11.4 本番／ステージングが要る・要注意な部分

  • テスト用に別の公式アカウント／LIFFチャネルを用意できると安全（本番の実ユーザーへテストPushが飛ぶ事故を防止）
  • リッチメニュー本番反映・実 Push 配信量（課金）・Flex 表示・shareTargetPicker は実機確認（ngrok で可）
  • ギフトカードの実際の発行・手渡し（店舗対応・券手配等）は自動テスト外＝運用テスト

11.5 テストしやすくする実装上の工夫（着手時に入れる）

  • Push 送信は必ず LineMessagingService 経由に統一（テストは Http::fake()）
  • IDトークン検証は interface/DI で差し替え可能に
  • 「1ヶ月後」は固定遅延でなく設定値＋Carbon::setTestNow()でテスト
  • ポイント／ギフトカードは Service に集約し Unit テスト
