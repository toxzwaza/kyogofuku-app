## 1. GTMタグのマスタ化

| 項目 | 修正前 | 修正後 |
|---|---|---|
| 入力方法 | イベント編集でGTM IDを直接入力（`修正前/01`） | 「GTMタグ」マスタから選択（`修正後/03`）。表示は「GTM ID ／ 紐付け店舗」 |
| マスタ管理 | なし | サイドバー「GTMタグ」：管理会社・GTM ID・メモ・紐付け店舗（複数）・有効（`修正後/01`,`02`） |
| 選択肢の絞り込み | — | イベントの開催店舗に紐付くタグ＋店舗未設定タグのみ。イベント18（岡山・城東）では福井店のタグは出ない |

| 項目 | 修正前 | 修正後 |

## 4. レビュー指摘への対応（reviewerエージェント → 村上承認済み）

| # | 指摘 | 対応 | 確認 |
|---|---|---|---|
| ① | 一括登録で同じ日・会場を重複送信すると二重作成 | store で日付×会場の重複を除外 | `store ignores duplicated cells` |
| ② | gtm_tag_id を送らない更新で LP の GTM が消える（本番反映直後の旧画面など） | キーがあるときだけ gtm_id を更新 | `update without gtm tag id keeps existing gtm id` |
| ③ | 無効化したタグが選択中だと「設定しない」表示になり、保存で外れる | 無効タグも返し、選択中のみ「（無効）」付きで表示＋注意文 | `options include inactive tags with flag` |
| ④ | タグID変更の同期で gtm_id が NULL のイベントが漏れる | whereNull も同期対象に | `changing tag id also fills linked events with null gtm id` |
| ⑤ | 移行が不正な既存値に弱い | データ移行を transaction 化、GTM-形式でない値はマスタ化せずイベント値を残す | 構文確認のみ（ローカル実データは全て正しい形式） |

対応しなかった指摘: 店舗管理者もタグを操作できる（会場マスタ等は権限チェック自体がなく、こちらの方が厳しい）、無効・店舗外のタグIDを直接送れば設定できる（画面からは選べず影響小）。
