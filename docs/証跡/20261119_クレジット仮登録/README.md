# 2026-11-19 クレジット契約の「仮登録」（担当の方に内容を確認中）

個人情報を含まない件数のみを記録する。画面のスクリーンショットは実データ（お客様名）が写るためリポジトリには置かない。

## 背景
2026-11-09 に担当の方へ送った追加確認リスト（24件）が確認中のため、
システムには仮に登録しておき、確認が済んだら画面から直せるようにしてほしいとの依頼。

## 変更
| 区分 | 内容 |
|---|---|
| DB | `credit_contracts` に `is_provisional`・`provisional_note`・`confirmed_at`・`confirmed_by` を追加（`2026_11_19_100000_add_provisional_to_credit_contracts`） |
| 一覧 | 「仮登録だけ」の絞り込み（件数つき。チェックすると状態は「すべて」）、「仮登録」バッジ（既存の「要確認」＝自社・現金の毎月確認とは別） |
| 支払状況の表・お客様のクレジット欄 | 「仮登録」バッジ |
| 契約の画面 | 仮登録の案内（確認していること）、「仮登録（担当の方に内容を確認中）」のチェックと確認内容。チェックを外して保存すると確認済み（確認した人・日時を記録） |
| 信販会社 | 仮登録のあいだだけ「未定」のまま保存できる。未定のまま仮登録を外そうとすると止める |
| 取り込み | 信販会社を判定できない契約（解約を除く）は仮登録で取り込む |
| コマンド | `php artisan credit:provisional <取り込み元,確認していること の CSV> [--unknown-company] [--dry-run]` |

## 現場で直された Excel の取り込み直し（同日）
Dropbox の「顧客クレジット」を zip で取り直し（11/19）、11/6 の zip と全ファイルを中身（セルの値）で比べた。

| 区分 | ファイル数 |
|---|---|
| 変わった | 42（うち 19 は保存し直しただけでセルの値は同じ） |
| 増えた | 13（新しいお客様 9・ファイル名の変更 4） |
| 無くなった | 6（ファイル名の変更 5・Excel が無くなった 1） |

- 取り込みのしくみ：`credit:import` に `--update`（取り込み済みのファイルも列ごとに比べ、増えた列は追加・変わった列は修正）と `--renames`（旧取り込み元,新取り込み元 の CSV）を追加
  - 画面で支払済にした月（確認した人あり）・仮登録の印・確認済みの契約はそのまま。Excel から消えた列は直さずレポートで知らせるだけ
- 指定ファイル（案件フォルダ `資料/取り込み指定/`）：`20261119_修正指定.csv`（合計の列が移ったファイル 1・2ファイルを1つにまとめて年がずれたファイル 1 を追加）、`20261119_ファイル名対応.csv`（5行）
- 手順：バックアップ `storage/app/credit-import/backups/20261119_localdb_prod_before_update.sql` → dry-run → 取り込み → `credit:provisional 20261119_仮登録指定.csv --unknown-company`

| 項目 | 件数 |
|---|---|
| 新しいお客様 | 9（契約 10） |
| 今のお客様に追加した契約 | 21 |
| 修正した契約 | 11（取り込み元の付け替え 10・支払予定の変更 1。うち担当の変更 2） |
| 仮登録 | 25（24＋信販会社の記載がない新規 1） |

- もう一度 dry-run すると追加 0・修正 0（二重に入らない）
- Excel が無くなった 1 ファイルの契約（仮登録中）は村上判断で**そのまま残す**（担当の方に事情を確認する）
- テスト：`CreditImportTest` に 2 件追加（列の追加・修正と、残すもの／ファイル名・列の付け替え）。CreditImportTest 8件・CreditTest 17件すべて成功

## 本番反映のとき
1. マイグレーション
2. 取り込みの後に `credit:provisional <仮登録指定.csv> --unknown-company`（先に `--dry-run`）
3. 同名ファイルの紐付け指定は 2 回に分けて実行（1回目で新規、2回目で同一人物のもう1ファイルを1回目のお客様IDへ）
4. 本番はローカル DB のデータを移す方針（2026-11-19 村上決定）。本番で取り込み直す場合は、新しい zip を元に `20261119_修正指定.csv` を使えば `--update`・`--renames` は不要
